## 2. PR 0: `HistogramBucket` and `±Inf`

- `pkg/metrics.HistogramBucket` gains `MarshalJSON` and `UnmarshalJSON` (`pkg/metrics/types.go`).
  - **Encoding:** an infinite bound is written as `"+Inf"` or `"-Inf"`. A finite bound goes through a method-less mirror struct whose field is `any` holding the `float64`, so the bytes are exactly those `encoding/json` produced before.
  - **Decoding:** a number, `"+Inf"` or `"-Inf"` is accepted. Any other string is refused with `histogram bucket: invalid upperBound "<s>": want a number, "+Inf" or "-Inf"`. A `null` or missing field leaves the value untouched, as encoding/json does for a plain `float64`.
- The tests are in `pkg/metrics/types_test.go`, in the external `metrics_test` package like the existing ones:
  - The round trip `[{0.25,3},{+Inf,5}]` is compared **byte for byte** through `assert.Equal` on `[]byte`, not `JSONEq`, and `math.IsInf(…, 1)` is checked after decoding.
  - Finite bounds are compared against a mirror struct without methods. The values tested are 0, -0, 5e-324, 1e-7, 0.005, 0.1, 0.25, 1, 2.5, 60, 1e21, -3.5 and MaxFloat64.
  - Refused strings: `"inf"`, `"Inf"`, `"+inf"`, `"-inf"`, `"NaN"`, `" +Inf"`, `"+Inf "`, `"1.5"` and `""`. Refused other types: `true`, `[]`, `{}` and `1e400`.
  - A full `Snapshot` holding the +Inf bucket now encodes, which is the original `json: unsupported value: +Inf` bug.
  - A `NaN` bound still fails to encode, on purpose.
- `--json` / `sanitizeBuckets` is untouched. `ember diff` decodes the `--json` output, which never holds an infinite bound, so it is unaffected.
- The CHANGELOG gets a new `## Unreleased` → `### Changed` section with a **[BC BREAK]** entry, in the style of `2e1a953`: the code and the CHANGELOG go in the same commit.

## 3. PR 1 part up to C1

### `internal/remote/wire.go`

- **Constants**
  - `ProtocolVersion = 1`.
  - Headers `Ember-Remote-Protocol` and `Ember-Remote-Session`.
  - Routes under `/remote/v1/`: `info`, `stream`, `config`, `certificates`.
  - Event names: `hello`, `snapshot`, `status`, `logs`.
  - Capabilities `snapshot`, `logs`, `config`, `certificates`. They are the same strings as the scopes; the scope type itself comes with `auth.go` at C2.
  - States `ok`, `stale`, `unreachable`, and `DefaultInstance = "default"`.
- **DTOs**
  - `Info`, `InstanceInfo` and `Hello`.
  - `WireSnapshot`, the envelope `{instance, fetchedAt, metricsFailed, snapshot}`.
  - `Status`, `LogBatch` and `WireLogEntry`.
  - `WireCertificate` and `ErrorResponse`.
  - Two-way conversions with `fetcher.LogEntry`, `fetcher.CertificateInfo` and `metrics.Snapshot`.
- **`Marshal`**
  - HTML escaping is **off**: a URI keeps its `&`. The rationale is in the code comment.
  - The decoders ignore unknown fields.
  - `DecodeInfo` refuses any `protocol` other than 1, **0 or missing included**, with `ErrUnsupportedProtocol` and the message `daemon speaks remote protocol N, this ember speaks 1`.
- **`FormatEventID` / `ParseEventID`**
  - The format is `<epoch>:<seq>`, split on the **last** `:`.
  - The parse is strict (`ParseUint`, no sign, no empty seq, no empty epoch), and a failure means "no resume point".
  - **Documented in the contract:** `seq` comes from **one counter per daemon epoch, shared by all sessions**. Without that, `Last-Event-ID` resume across a reconnect, which opens a new session, would be meaningless. Seqs are increasing but not contiguous within a session.
- **Things that deliberately do not travel**
  - `Snapshot.Metrics.Extra` (`json:"-"`): the raw Prometheus families for plugins, and plugins are out of scope in remote mode.
  - The body's own `MetricsFailed` is cleared by `NewWireSnapshot`. The envelope carries it, and `ToSnapshot()` restores it.

### Golden contract (`internal/remote/testdata/wire/v1/*.json`)

- There is one file per wire type: `info`, `hello`, `snapshot`, `status`, `logs`, `certificate` and `error`.
- **The golden files are indented.** The test encodes with the real `Marshal`, the one that will produce the bytes sent, then applies `json.Indent`, and compares the result as a string with the file. `json.Indent` only adds whitespace between tokens, so key order, number formatting and escaping stay pinned byte for byte. `-update` is opt-in (`go test ./internal/remote -run TestWireGolden -update`).
- `TestWireFixturesCoverEveryField` enumerates by reflection every JSON field path of every wire type. It walks pointers, slices, maps and `time.Time`, and skips `json:"-"`. It then requires each path to hold a non-zero value somewhere in the fixtures. Adding a field to, say, `metrics.HostMetrics` therefore fails this test until the fixture, and so the golden file, is updated. **This was checked by mutation:** removing `TTFBCount` from the fixture fails both tests with `Should be empty, but was [snapshot.Snapshot.Metrics.Hosts[].TTFBCount]`.
- The snapshot fixture holds a `+Inf` bucket, a busy thread with URI, method and memory, and `metricsFailed: true`, as § 9.1 asks.
- `TestGoldenFilesHaveNoStrayCases` flags a golden file left without a test case.
- `TestWireConstantsArePinned` asserts every route, header, event, capability and state name, plus `DefaultInstance` and `ProtocolVersion`, against a string literal. Every other test goes through the constants themselves, so without it a rename would pass the whole suite.

### `internal/remote/sse.go`

- **`WriteEvent`**
  - The whole event goes out in **a single `Write`**, so a per-event write deadline covers all of it.
  - It returns the bytes written, for the `bytes` field of the audit.
  - It refuses an id containing CR, LF or NUL, and a type containing CR or LF: no line injection.
  - Data lines are split on any line terminator. `WriteComment` produces the `: ping` keep-alive.
- **`Reader`**
  - It follows the WHATWG grammar through a `bufio.Scanner` with a custom split: `\r\n`, `\n`, a lone `\r`, and a `\r` at the end of a read that waits for the next byte.
  - It skips comments and strips a leading BOM.
  - The id is sticky and an id containing NUL is ignored.
  - An event without data is not dispatched, and an empty type defaults to `message`.
- **Bounds** (`DefaultMaxEventSize` = 8 MiB, configurable)
  - A single line over the bound fails with `ErrEventTooLarge`, through `bufio.ErrTooLong` and the scanner's maximum buffer size.
  - Cumulated data over several `data:` lines is bounded too.
  - Memory therefore stays at about 2× the bound, whatever the input.
- **Errors**
  - Every error is **sticky**: after `ErrEventTooLarge` the reader never reports `io.EOF`.
  - End of stream between two events gives `io.EOF`. End of stream inside an event gives `io.ErrUnexpectedEOF`, and the partial event is discarded.

### Fuzz

- `FuzzSSEReader` checks four things:
  - no panic;
  - no event over the bound (256 bytes in the fuzz);
  - a failed reader stays failed;
  - at most one event per input byte, which proves the reader consumes its input.
- `FuzzDecodeWireSnapshot` checks two things:
  - no panic;
  - whatever decodes must encode again, which is the ±Inf and NaN property.
- Both targets are registered in `scripts/run_fuzz.sh`.

### Note for C4

`Reader.Next` skips the `: ping` comments, so a caller cannot see them. The client's dead-stream detection (C4) will therefore reset its idle timer on every `Read` of the response body, not on every `Next`. The reader API is deliberately enough for that.

## 5. Deviations from the spec

None of them is intended. There are two points of interpretation:

1. **Golden files are indented, not the raw wire bytes.** The justification is in § 3 above: the comparison is still exact on everything except inter-token whitespace, and the wire itself is compact.
2. **`protocol: 0` (or a missing field) is refused like `protocol: 2`.** The spec only says "refuse an unknown `protocol`". 0 is not a version that exists, so it is treated as unknown.
3. **`pkg/metrics/types_test.go` is in the external `metrics_test` package**, although § 9 asks for tests in the internal package. Every existing test file of `pkg/metrics` is external (`parse_test.go`, `parse_fuzz_test.go`, with `export_test.go` as the bridge). This package is the public plugin API, and testing it from outside is the point. `internal/remote` tests are in the internal package, as asked.

## 6. Questions: contract decisions the spec does not fix

None of them blocks C2. Each one is now frozen by a golden file, so a change later means updating the golden file before PR 1 ships.

1. **Error body.** 426, 400 and 404 answer `{"error", "supportedProtocols"?, "instances"?}` (`ErrorResponse`). Is that shape acceptable, and should 401, 403, 429 and 503 use it too, as I intend?
2. **Optional fields.** Only `status.error`, `logEntry.rawLine` and `logEntry.parseError` use `omitempty`. Every other field is always present, including `status.since`, which is always set. `omitzero` is not used anywhere: no optional `time.Time` so far.
   - **`null` versus `[]`:** a nil slice encodes as `null` (`info.scopes`, `info.capabilities`, `info.instances`, `logs.entries`, `certificate.dnsNames`). The golden files cannot see it, since every fixture is non-nil. Must the daemon always send `[]`? If so, I would normalise in the constructors at C3.
3. **Certificates envelope.** `WireCertificate` is defined, but the body of `GET /remote/v1/certificates` is not yet: a bare array, or `{"certificates": [...]}`? I plan to add an object envelope in PR 3 for extensibility, unless you object.
4. **Max event size: 8 MiB** (`DefaultMaxEventSize`). Is it adequate for the largest deployments you have in mind?
5. **`retry:` is ignored** by the reader. The client paces itself (1 s to 30 s, § 7.1), and the daemon will not send it.
6. **HTML escaping is off** in `Marshal`: `&`, `<` and `>` are sent raw, which is valid JSON and not rendered by a browser.
7. **`Info.instances[].interval`** travels as a Go duration string (`"1s"`), matching the example in § 5.1. Decoding refuses a number.
8. **`WireLogEntry` JSON names** are my choice, since § 5.4 does not list them: `timestamp`, `level`, `logger`, `message`, `host`, `method`, `uri`, `status`, `duration` (seconds, float), `size`, `remoteIp`, `rawLine`, `parseError`. `WireCertificate` uses `isCa`, following the camelCase rule and `processRssBytes` in `pkg/metrics`.
9. **Thread states keep their PascalCase keys** (`ThreadDebugStates`, `CurrentURI`…) because the wire snapshot is the JSON of `metrics.Snapshot`, whose tags mirror FrankenPHP's payload. § 5 says "fields in camelCase", but § 5.4 says the snapshot is the encoding of `metrics.Snapshot`. I followed § 5.4. Please confirm.
